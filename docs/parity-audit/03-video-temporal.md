# Video, temporal filters, stabilization, and audio — parity audit

**Area ID:** `video-temporal`
**Comparison rule:** The browser implementation is the intended product behavior. This is a static source audit only; no runtime tests were run and no source was changed.

## Scope

- **Web:** `src/app/player.ts`, `src/app/audio.ts`, `src/app/mtVideo.ts`, `src/engine/filters/temporal.ts`, `src/engine/sources/{avi,dvr,bitstream,yuv,types,index,mbsource}.ts`, `src/engine/stream.ts`, `src/engine/frame.ts`, `src/shared/filters.ts`, `src/panels/PlayerPanel.ts`; related decoder conversion uses `src/engine/filters/basic.ts`, `src/engine/kernels/{fft,geometry}.ts`, and the source image decoder.
- **Native:** `android-native/app/`, `android-native/lib/`, `android-native/components/`, and `android-native/package.json`.

## Original browser capabilities

- **Playback/navigation:** Play/pause; first/last and single or configurable-stride stepping in frames or seconds; direct frame/time entry; looping; 0.01×–16× speed presets and custom speeds; optional no-frame-dropping playback; and optional In/Out-limited playback with set/go/clear points. At <1× the player never skips frames; ≥1× may drop frames unless “Play Every Frame” is selected. Audio is synchronized only at 1×.
- **Timeline:** Click/drag to seek, frame/time hover hint, current-frame cursor, In/Out region markers, bookmark markers, and a separately seekable audio display. The audio display can show min/max waveform or envelope.
- **Audio:** `mediabunny` finds/decodes the primary audio track; 4,096 min/max peak bins derived from channel 0 power the waveform; Web Audio streams scheduled decoded buffers for playback, with mute and volume. Audio is intentionally silent at non-1× speeds. This is audio-track playback, not evidence analysis of audio samples.
- **Frame/source handling:** Mediabunny demuxes common containers and indexes video samples in presentation order using packet PTS; WebCodecs decodes indexed frames, exposing I/P/B type metadata and (where available) raw YUV planes. An HTML `<video>` seek/canvas fallback accepts browser-supported codecs but is explicitly time-based/approximate and bypasses the app's matrix/range/chroma conversion when it only returns canvas RGB. AVI has a RIFF/OpenDML/index-or-scan reader; Motion JPEG and uncompressed RGB/gray/YUY2/UYVY/I420/YV12/NV12 are decoded directly. AVI H.264/H.265 is remuxed. “Convert DVR” recognizes Hikvision/MPEG-PS, Dahua DHAV, Annex-B/raw H.264/H.265, and concatenated MJPEG; compressed streams are remuxed to MP4 without re-encoding. The browser path rejects DVR files over 1.8 GB.
- **Temporal operations** (`temporalFilters` and filter catalog): single/range/sparse selection; I/P/B selection; duplicate removal; similarity demultiplexing; motion/still selection; deinterlace (linear, duplicate, blend, bob), field separation/interleave; frame difference; local ROI/template-match and global phase-correlation stabilization (reference frame, subpixel, border fill); frame averaging (all-frame mean/median/sigma-clipped or moving window); temporal smoothing (2–31-frame mean/Gaussian/median, moving-object protection and optional protected-area mask); multi-frame subpixel super-resolution (2–4×); nominal or converted frame rate; reverse and freeze frame. Frame-wise operations use the float RGBA `Frame` stream abstraction; the temporal filters are render/preview processing and do not, by themselves, establish a verified forensic export.
- **Color fidelity scope:** Raw/software-decoded YUV is converted by app code with explicit matrix, full/limited range, chroma siting/reconstruction (nearest/bilinear/bicubic), and optional HDR handling in the source pipeline. If the browser selects hardware RGB output or the media-element canvas fallback, that exact-plane path is not available; the UI metadata/warnings distinguish these conversions.

## Native current implementation

The native app is a single Expo Router tab (`app/(tabs)/index.tsx`) for local **PNG still-image** evidence: it picks a PNG, hashes original bytes, decodes exact PNG samples, applies the reference Negative transform, exports a 16-bit PNG, and verifies every saved sample by reading it back. The viewer is a React Native `<Image>` preview. There is no video file picker, video view/player, frame/PTS model, timeline, temporal-filter engine, stabilization, waveform, audio decode/playback, or AVI/DVR/bitstream decoder in the inspected native app/lib/components. The only native engine pipeline is `lib/engine/imagePipeline.ts`; `lib/project/evidenceIO.ts` scopes input to `image/png`. `expo-video` and `expo-audio` are declared dependencies in `package.json`, but are not imported by the current route or media pipeline and therefore are not implementation evidence or parity.

## Specific gaps

1. All video playback and frame navigation controls/timeline affordances above are absent natively; consequently no frame-accurate or approximate video behavior is currently shipped there.
2. No native audio track extraction, waveform/envelope generation, synchronized 1× playback, mute/volume, or playback-speed handling exists.
3. None of the browser temporal filters, including local/global stabilization, can be run or previewed natively. Native verified Negative is a still-image operation, not a proxy for video processing parity.
4. Native has no video demux/index/source provider, metadata/PTS/frame-type display, AVIs, DVR conversion/remux path, YUV conversion options, or browser-fallback warning equivalent.
5. Web playback preview and forensic processing must not be conflated: WebCodecs indexed PTS can support frame-exact decoded-frame access, but hardware/browser-converted pixels and especially `<video>` seek/canvas fallback are weaker; native `expo-video` would likewise provide playback, not automatically exact frame extraction, color provenance, or bit-exact processing.
6. The existing native export verification covers its generated PNG samples and saved-file read-back only. It does not verify video decoding, the source video remaining unchanged, processed-video pixels, timestamps, or audio synchronization.

## Dependencies and risks

- Original decoder stack depends on `mediabunny` (`1.61.5` in the web package), browser WebCodecs/`VideoDecoder`/`VideoFrame`/`VideoSampleSink`, and optionally HTML media elements; audio uses Mediabunny plus Web Audio. WebCodecs is not a React Native API. The declared Expo video/audio packages are native playback APIs, not drop-in implementations of indexed frame reads, exact YUV plane access, PTS, or the browser filter stream.
- A feasible Android architecture is split by purpose: use `expo-video` only for an explicitly approximate playback/seek preview; use Android `MediaExtractor` + `MediaCodec` (likely a Kotlin native module, with device/API compatibility coverage) for indexed PTS/frame processing; implement/port custom AVI/DVR parsing separately. Vendor codec support, B-frame presentation order, decoder output surfaces, color metadata, bit depth, HDR, and `YUV_420_888` plane strides can vary across Android devices. A successful visual decode is not proof of pixel-for-pixel browser parity.
- Forensic exactness requires defined guarantees before porting: retain/hash original bytes, expose original PTS and decoded-frame provenance, avoid silent conversions, record matrix/range/chroma/HDR decisions, distinguish decoder-produced samples from rendered RGB, and label approximate playback separately from processed/verified results. Require golden frame/sample comparisons and output read-back verification; do not call preview “verified.”
- Memory is material: temporal smoothing can hold up to a 512 MiB window by default before using a streamed path; super-resolution accumulates multi-frame float data; source caches are 128–192 MiB. Original DVR conversion buffers the whole input/output (up to 1.8 GB); native should use SAF/document URIs and bounded/streaming reads rather than duplicating large clips in JS/base64. Cancellation and Android memory-pressure behavior need explicit treatment.
- Keep media local/offline by design. Current PNG flow picks a local document and processes bytes locally; it does not upload evidence. The package also contains networking/auth/server dependencies, so “offline” should be verified for the release configuration and must not be inferred solely from the home-screen badge. Any future video pathway should not send evidence bytes or derived frames to the app server, analytics, or cloud without explicit authorization.
- Audio/video clocking and sample-rate conversion are another independent risk: a native preview can be synchronized by its media player, but recreating the browser’s streamed audio behavior at exact frame seeks and implementing waveform peaks on-device needs a defined timestamp/sample mapping and tests. The browser only plays audio at normal speed, an intentional constraint to preserve.

## Recommended port sequence

1. **Specify boundaries and provenance first.** Define a versioned video evidence record (URI, size/hash, container/codec, PTS/timebase, frame index, decoder path, color metadata) and UI language separating playback preview from forensic decoded-frame processing. Keep files local; do not alter source bytes.
2. **Add read-only video intake and metadata, no processing.** Use Android document picker/SAF without base64-copying large media; hash original bytes incrementally; inspect supported MP4 first with `MediaExtractor`; show explicit unsupported-codec/approximate status. Verify cancel, permission revocation, rotation/reopen, large files, and offline behavior.
3. **Build a frame-index/decoder spike behind a native adapter.** Decode selected frames via `MediaExtractor`/`MediaCodec`; report PTS, frame index, dimensions, format/strides/color aspects, keyframe status and decoder hardware/software path. Compare exact fixtures on a pinned reference device and define where results are device-specific; do not claim exactness for preview output.
4. **Implement still-like single-frame inspection and navigation.** Render decoded frames with a visible frame/PTS display, step/seek and timeline first; if using `expo-video` for normal playback, label it playback-only and keep it distinct from the frame-extraction pipeline. Test seek results against indexed PTS, including VFR/B-frame clips.
5. **Port a minimal deterministic temporal kernel.** Start with frame difference and global stabilization, then local stabilization; define float/rounding/interpolation and border-fill contracts, use bounded frame caches/cancellation, and compare output samples against browser golden results. No unverified export at this stage.
6. **Add integration filters one at a time.** Frame averaging, motion-protected temporal smoothing, selection/range/frame-rate transforms, deinterlace/field operations, then super-resolution. Expose progress/cancel and parameter parity; add an explicit mask preview for smoothing.
7. **Port audio last as a separately tested subsystem.** Extract audio metadata, native synchronized 1× playback, mute/volume, then peak/envelope data and seek mapping. Keep speed≠1× muted unless pitch/time-stretch semantics are separately specified.
8. **Only then design processing export.** Save a new artifact, preserve original, write a processing/provenance manifest, and reopen/read back to verify frame count, timestamps, pixel samples, and (if included) audio before any “verified” label.

- Add decoder fixtures/functions for source media: synthesize/retain valid indexed and indexless/OpenDML AVI (the existing `tests/manual/large-avi.ts` has `frameRGB`/`parseAvi` coverage but is a manual >4 GB generator, not a compact committed video corpus); H.264/H.265 Annex-B with B-frames and PTS ordering; supported H.264/HEVC MP4/MKV; MJPEG AVI; and raw/gray/YUV AVI. Verify track selection, peak bins/envelope, seek/time-to-sample mapping, playback starts/stops on pause/seek/range/loop, mute/volume, and silent audio behavior at non-1×. Test timeline In/Out, bookmarks, click/drag seeking, frame/time entry and frame/seconds stepping as separate player-state tests.
- Add export verification tests only when export exists: original byte hash unchanged; generated media reopens; frame count and PTS match the export plan; pixel/sample digest/read-back equals expected; audio track is preserved or explicitly omitted and disclosed.
