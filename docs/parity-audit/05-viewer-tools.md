# Parity audit: Viewer, inspection, measurement and annotation

**Area ID:** `viewer-tools`
**Comparison rule:** The existing browser implementation is intended behavior. Source inspection only: no application source was modified, dependencies were not installed, and no runtime tests/build/device run was performed.

## Scope

**Web:** `src/panels/ViewerPanel.ts`, `src/panels/ToolsPanel.ts`, `src/engine/pixelcheck.ts`, `src/engine/kernels/{color,conv,draw,fft,geometry,jpeg}.ts`, and directly used UI helpers (`src/ui/{controls,dom,icons,menu,touch}.ts`). Relevant contracts/wiring: `src/app/store.ts`, `src/shared/filters.ts`, `src/engine/engine.ts`, and `src/engine/sources/image.ts`.

**Native:** `android-native/app/(tabs)/index.tsx`, `_layout.tsx`, `android-native/components/`, and `android-native/lib/{codecs,engine,project}/` modules directly used by its one Evidence screen. The app exposes only the Evidence tab; generic shared components do not implement viewer tools.

## Intended browser behavior

- **Viewer/navigation:** Renders the selected frame at a chain/filter step; supports chain tabs (rename, duplicate, open another viewer, delete), input/output review, per-chain zoom/pan state, Fit, 6.25–3200% presets, slider/step zoom, zoom-to-drag-rectangle, mouse-wheel zoom around cursor, middle/space drag pan, navigator viewport, and context-menu zoom/display choices. Sharp, nearest-neighbor and bilinear are display-only interpolation. Pointer/touch paths include pinch zoom+pan, double-tap zoom/fit, long-press context menu and touch-sized handles.
- **Pointer inspector:** Image-space fractional cursor coordinates and the RGB sample at the floored pixel in the current render; BT.601 luma display value, color swatch, frame position/type/timestamp, dimensions, grayscale/color classification, and copyable frame MD5. This MD5 is over the rendered frame’s **8-bit RGB** buffer, not original source bytes or the full-precision processing frame.
- **Histogram/saturation:** All/R/G/B/BT.601-Y histograms, min/max/mean/stddev, per-channel MD5 (8-bit channels), and clipped black/white percentages. These are derived from the render’s 8-bit display conversion. Saturated-pixel overlay marks channel values exactly 0 or 255; it is not a raw sensor/code-value histogram.
- **File and frame analysis:** File Info shows source metadata and can copy the table or compute file hashes. Frame Analysis for video shows frame type (I/P/B/unknown), PTS, encoded size, current frame, GOP lengths, average frame sizes, frame interval variability and duplicate timestamps; clicking navigates source frames where supported.
- **Measurement/annotation tools:** Selector can draw/edit a clipped integer rectangle, set coordinates numerically, select all/clear, zoom/center, crop, or add Hide Selection. Ruler reports endpoints, Δx/Δy, Euclidean length and angle in pixels; it can seed a calibrated Measure 1D filter. Polygon reports vertex count, pixel perimeter and shoelace area. Intensity Profile plots sampled R/G/B along a line from the rendered 8-bit frame. Crosshair follows cursor or locks/unlocks for frame comparison.
- **Filter overlays:** Selected filters can expose editable points, point sets/polylines, lines and rectangles on the image; drag handles edit filter parameters, double-activate removes point-set vertices, and contextual actions clear overlays. Examples include Fourier notches (on spectrum), Measure 1D/2D reference/measured geometry and motion-deblur blur trail. Filter parameters remain processing state; viewer overlays visualize/edit them rather than annotating evidence pixels.
- **Preview versus exact result:** ViewerPanel may place a WebGPU parameter preview on screen while tuning a supported filter, explicitly badges it, then replaces it with the engine render. The code limits this to display while adjusting; render outputs, measurements and hashes use exact engine results. Engine render converts the processing frame to 8-bit RGBA for display/statistics; this is not the same as retaining or exporting original high-bit-depth samples. `pixelcheck.ts` self-tests whether browser canvas/VideoFrame readback changes pixels; browser image source loading can use exact PNG/TIFF paths, checked WebCodecs, or a canvas fallback (which may be perturbed).

## Native implementation now

- The only route is one Evidence screen. It picks a single PNG through Expo DocumentPicker, reads complete source bytes into JS memory, checks picker size when supplied and keeps source bytes for hashes; UI explicitly says source is unchanged. No video, chain/filter history, frame player, alternative viewers or tool panel is exposed.
- The viewer is a fixed-height React Native `<Image resizeMode="contain">` of the selected local URI or generated negative PNG. There are no zoom/pan/pinch/navigator/context-menu gestures, pixel-coordinate sampling, display interpolation choices, cursor/selection state, overlay canvas/SVG, annotation or measurement controls. `<Image>` is a preview; it is not used for sample readback or verification.
- The screen displays file name/byte count and source MD5/SHA-1/SHA-256 after processing, then supports one `Negative` action. `decodePngExact` reads stored PNG samples (including 16-bit values divided by 257 into float RGBA), rejects APNG for processing, and `runNegativeExport` applies `255-RGB`, writes 16-bit RGB PNG, checks every in-memory sample, saves through Android SAF, reads the chosen file back, and compares every sample. If the user cancels SAF destination selection, the in-memory-verified export remains previewable but is labeled unsaved. These are processing/export checks, not viewer pixel inspection or general forensic verification.
- Existing `android-native/tests/forensics/imagePipeline.test.ts` covers hash vectors, one synthetic compressed 1×1 RGB PNG fixture, Negative/output samples, RGB16 rounding/clamping, stored PNG round-trip and Base64 round-trip. There are no viewer/gesture/overlay/measurement tests in the scoped implementation.

## Specific gaps

1. Entire browser inspection/tool surface is absent natively: pointer values/coordinates, histogram/stats/clipping, file metadata/hash panel, video frame analysis, zoom/navigation, selection, ruler, polygon, profile and crosshair.
2. Native preview is not a pixel-addressable frame buffer. It cannot safely back inspection, sampled profiles, histogram or measurements; those require a defined exact decoded/processed sample buffer and coordinate transform, separate from `<Image>` rendering.
3. No editable filter graph or overlay model exists, so filter parameter handles, calibrated Measure 1D/2D drawings, Fourier-spectrum notch points and blur-trail geometry cannot be represented. Existing native Negative is not equivalent to the browser’s arbitrary chain/filter viewer.
4. Web pointer values describe current rendered 8-bit output; the frame MD5 likewise hashes 8-bit rendered RGB. Native displayed hashes are source **file-byte** hashes, and its output sample MD5 hashes generated RGB16 samples. They are different domains and must not be labeled interchangeably.
5. Native PNG decoder’s exact stored samples are converted to 0–255 float values (`16-bit / 257`) before Negative and then mapped to RGB16 via `round(v*257)`. That quantization cannot preserve all original 16-bit sample distinctions. “PIXELS VERIFIED” currently means the generated output matches the generated expected samples, not that source precision was retained or that browser/native outputs are parity-identical.
6. Native screen reports dimensions/source bit depth only after processing; it does not present browser-equivalent source metadata, per-render statistics, frame timestamps or selectable output steps.

## Dependencies and risks

- **Forensic exactness:** Keep three concepts separate: displayed preview, exact decoded/processed samples, and verified saved-file samples. Do not use React Native `Image`/platform bitmap pixels as the numerical source. Define coordinate origin, pixel-center/flooring, orientation policy, alpha treatment, color-profile policy and scaling before adding measurements. Browser Profile samples rounded pixel positions from its 8-bit rendered buffer; exact native parity needs goldens against that stated domain or a deliberately documented higher-precision change.
- **Hash semantics:** Name every digest’s subject and representation (source file bytes, rendered RGB8 frame, individual channel, expected RGB16 sample bytes, saved output file bytes). A matching algorithm name alone does not establish identity. Existing native output verification checks expected decoded samples and their MD5; it does not compare a full output-file hash to browser output.
- **Offline/security:** This screen’s evidence path is local (DocumentPicker/FileSystem and pure JS codecs); no upload is invoked by the inspected screen. Its OFFLINE badge is not proof of whole-app offline behavior: native package has server/auth/network dependencies in other modules. Preserve no-implicit-upload, exclude image bytes/URIs/case data from logs/analytics, and test offline operation. Source is copied to cache and retained in screen JS state; establish cache cleanup, retention, backup and secure-storage policy for sensitive evidence.
- **Android feasibility/performance:** Touch interactions are feasible with React Native Gesture Handler/Reanimated and overlays with SVG/canvas/native drawing, but must be transformed consistently with contain-fit, device density, crop and zoom. Full PNG bytes plus float RGBA and per-pixel stats can multiply memory; Base64 read/write adds copies. Use bounded buffers/streaming or native decoding for large evidence, and avoid recomputing full histograms on every pointer move. SAF/provider cancellation, permission and read-back behavior require physical-device tests.
- **Scope boundary:** The browser includes stills, animation, video and filter chains; native currently permits a PNG-only evidence workflow. Do not present tool parity as complete until the relevant source/processing types and frame-navigation model exist.

## Recommended port sequence (small, testable increments)

1. **Define sample/display contract:** Document native coordinate ↔ decoded pixel mapping, pixel selection rule, PNG orientation/color/alpha policy and precision. Add browser-golden fixtures for RGB8, gray, palette/transparency and RGB16 before adding UI.
2. **Interactive image viewport only:** Add fit, 100%/step zoom, pan and pinch with a stable image-to-screen transform; unit-test transform/inverse/edge clamping, then test touch behavior on Android. Label interpolation as display-only.
3. **Exact frame buffer + pointer inspector:** Expose current exact decoded/processed samples separately from `<Image>`; add coordinates, RGB/luma and swatch. Verify pixel-center/flooring and edge/outside behavior against fixtures; retain source-byte hashes as a separate labeled group.
4. **Histogram and clipping:** Compute deterministic bins/statistics from explicitly selected sample domain; add per-channel and luma modes, saturation counts, and tests against independent expected arrays. Do not derive them from scaled preview pixels.
5. **Selection and basic measurement:** Add rectangular selection/numeric dimensions, ruler (Δx/Δy/length/angle), polygon area/perimeter and crosshair. Add round-trip coordinate tests at fit, fractional zoom, pan, density changes and image boundaries.
6. **Profile and frame/file info:** Add sampled RGB line profile and richer source metadata/hash detail; port video frame analysis only after native decoder/frame-table support, otherwise leave it explicitly unavailable.
7. **Filter overlays after processing model:** Introduce filter parameters/history, overlay metadata and editing state, then port one overlay type at a time (point/line/rect/points), including undo/serialization. Add Measure 1D/2D only with calibration and geometry goldens. Keep WebGPU/display previews from becoming inputs to analysis or hashes.
8. **Acceptance and provenance:** Record exact algorithm/sample domain, source and output byte hashes separately, and preview/verified status. Run Android SAF and device interaction tests; report each unsupported browser workflow rather than implying broad parity.

## Tests needed

- **Existing web references (not run):** `tests/pngdecode.test.ts` exercises PNG depths/color types, row filters, Adam7, transparency and truncation; `tests/perf.test.ts` includes display histogram equivalence and `matchTemplate`/parallel comparison. `src/engine/pixelcheck.ts` exports `canvasReadbackExact()` and `videoFrameReadbackExact()` but no dedicated test file was found. Preserve output-domain distinctions in viewer tests.
- **Existing native baseline (not run):** `android-native/tests/forensics/imagePipeline.test.ts`: `compressedRgbPng`, `runNegativeExport`, `verifyPngExport`, `frameToRgb16`, digest vectors, PNG round-trip and Base64 round-trip. It does not cover SAF or view gestures.
- **Add viewport tests:** pure image/screen coordinate conversions, fit/actual-pixel/fractional zoom, pan/pinch anchoring, contain letterboxing, crop boundaries, orientation changes and density. Device tests for single-finger pan versus tool drag, pinch, double tap, rotation and accessibility.
- **Add inspection fixtures:** known RGB/gray/alpha/RGB16 PNGs with exact expected pointer RGB/luma, histogram bins, min/max/mean/stddev/clipped counts, channel hashes and sampling behavior at edges; explicitly test 16-bit quantization handling and mismatch refusal.
- **Add measurement tests:** ruler length/angle and calibration; polygon shoelace area/perimeter for clockwise/counterclockwise/degenerate shapes; line-profile sample sequence at horizontal, vertical, diagonal and out-of-bounds endpoints; selection clipping and crop mapping.
- **Add overlay integration tests after filter model exists:** create/move/resize/clear point, line, rectangle and points; Fourier notches on spectrum coordinates; Measure 1D/2D calibration; overlay edits persist/undo without changing source bytes. Assert a display preview is never accepted as an exact analysis/hash result.
- **Add Android storage/offline tests:** SAF permission denied/cancel, actual saved-file read-back, process interruption and cache cleanup; airplane-mode workflow with network instrumentation proving evidence bytes are not transmitted.
