# LUCID and MCP (Model Context Protocol)

LUCID speaks MCP in both directions:

| Direction | What | Where |
|---|---|---|
| AI applications → LUCID | LUCID as an **MCP server**: Claude Desktop, Claude Code, Cursor, VS Code, Windsurf, Gemini CLI, Codex… operate the open LUCID window | `mcp/lucid-mcp.mjs` (bridge) + the LUCID tab |
| LUCID → MCP servers | LUCID's assistant as an **MCP client**: tools of other MCP servers next to LUCID's own | AI panel › MCP › Add server |
| Browser agents → LUCID | **WebMCP** (`document.modelContext`, Chrome 146+ with WebMCP) and `window.lucid.mcp` for Playwright MCP / Chrome DevTools MCP | built into the page |

## The bridge

A web page cannot listen on a port or be started by an MCP client, so `lucid-mcp.mjs` (Node 18+, no dependencies)
does it and relays each call to the LUCID tab, where the examiner's settings apply.

```
node mcp/lucid-mcp.mjs           # stdio MCP server (MCP clients start it like this) + web server
node mcp/lucid-mcp.mjs --http    # web server only: LUCID at http://127.0.0.1:47800/, MCP at /mcp
```

Options: `--port 47800` · `--host 127.0.0.1` · `--app <dir>` (default `../release`, run `npm run build` first) ·
`--config <servers.json>` · `--allow-origin <origin>` (browser-based MCP clients) · `--token <secret>` (require
`Authorization: Bearer <secret>` on `/mcp`) · `--no-open`. Environment: `LUCID_MCP_PORT`, `LUCID_MCP_TOKEN`,
`LUCID_APP_DIR`, `LUCID_MCP_HOME` (default `~/.lucid-mcp`).

* It **serves LUCID itself**: open `http://127.0.0.1:47800/` and that tab links automatically (same origin: no CORS,
  mixed-content or private-network prompts). When a tool is used and no tab is linked, it opens that address.
* A LUCID tab on another origin (e.g. a hosted copy) links in AI panel › MCP › *Bridge* with the **pairing code**
  printed at start (also in `~/.lucid-mcp/pairing.json`).
* One tab is operated at a time (the most recently linked; others are on standby).
* A second MCP client launching the bridge while one runs relays through the running one.

### Protocol

* Transports: **stdio** and **Streamable HTTP** at `/mcp` (JSON responses; `GET` → 405).
* **2026-07-28** (modern): no handshake, `server/discover`, `_meta` protocol version / client info on every request,
  `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` (Base64 sentinel decoded) validated against the body
  (`-32020 HeaderMismatch`), `-32022 UnsupportedProtocolVersion` with the supported list, `resultType`, `ttlMs` and
  `cacheScope` on results, 404 + `-32601` for unknown methods.
* **2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05** (legacy): `initialize` / `notifications/initialized`,
  `Mcp-Session-Id`, `DELETE` ends a session, `notifications/cancelled`, `tools/list_changed` on stdio when a tab
  links with its live catalog.
* Security: binds to 127.0.0.1; rejects foreign `Origin` (403) and `Host` headers (DNS rebinding); optional bearer
  token; pages on other origins need the pairing code to act as a LUCID tab or use hosted servers; static files
  cannot be read outside the app folder.

### What clients get

* **Tools**: the 31 tools of LUCID's assistant (`get_state`, `get_source_info`, `get_frame_stats`, `view_frame`,
  `list_filters`, `get_filter_schema`, `add_filter`, `set_filter_params`, `go_to_frame`, `playback`, `export`,
  `ask_user`, …) with `readOnlyHint` / `destructiveHint` / `idempotentHint` annotations. Listed from
  `mcp/catalog.json` (generated by `npm run build`) before a tab links, then from the tab.
* **Resources**: `lucid://project`, `lucid://audit-log`, `lucid://filters`, `lucid://help`.
* **Prompts**: `assess_evidence`, `enhance_region`, `stabilize_and_integrate`, `prepare_report`.

### The examiner decides (AI panel › MCP)

* **Allow**: *Off* · *Read only* · *Ask me before each change* (default) · *Full control* (each change undoable).
* The first call of each application asks once: **Allow / Read-only / Deny**.
* `view_frame` sends an image only after frame-sharing consent for that application.
* `open_media` and `export` need the examiner's click in LUCID.
* Every call appears in the AI panel (labelled with the application) and in the project's audit log, which the
  report prints (AI Assistance).

## Client configurations

Replace `/path/to/lucid` with the folder that contains `mcp/` and `release/`.

**Claude Desktop** (`claude_desktop_config.json`), **Cursor** (`~/.cursor/mcp.json`), **Windsurf**, **Cline**:
```json
{ "mcpServers": { "lucid": { "command": "node", "args": ["/path/to/lucid/mcp/lucid-mcp.mjs"] } } }
```
**Claude Code**:
```
claude mcp add lucid -- node /path/to/lucid/mcp/lucid-mcp.mjs
claude mcp add --transport http lucid http://127.0.0.1:47800/mcp     # bridge already running (--http)
```
**VS Code** (`.vscode/mcp.json`):
```json
{ "servers": { "lucid": { "type": "stdio", "command": "node", "args": ["/path/to/lucid/mcp/lucid-mcp.mjs"] } } }
```
**Gemini CLI** (`~/.gemini/settings.json`): `{ "mcpServers": { "lucid": { "httpUrl": "http://127.0.0.1:47800/mcp" } } }`

**Codex CLI** (`~/.codex/config.toml`):
```toml
[mcp_servers.lucid]
command = "node"
args = ["/path/to/lucid/mcp/lucid-mcp.mjs"]
```
**ChatGPT and other cloud-hosted clients** only reach public HTTPS servers: expose `http://127.0.0.1:47800/mcp`
through a tunnel only with `--token` set, and consider what that exposes.

## LUCID's assistant as an MCP client

AI panel › MCP › **Add server** (URL, transport, authorization, headers, approval) or **Add from bridge**.

* Streamable HTTP, modern era detected with `server/discover` (falls back to `initialize` per the 2026-07-28
  backward-compatibility rules), legacy sessions, the optional legacy GET stream, and HTTP+SSE (2024-11-05).
* Multi Round-Trip Requests and legacy server requests: **elicitation** questions go to the examiner; `roots/list`
  answers with no roots; sampling is not offered.
* `x-mcp-header` parameters mirrored into `Mcp-Param-*` headers; tools with invalid annotations are excluded.
* Authorization: headers, bearer tokens, **OAuth 2.1** (RFC 9728 protected resource metadata, RFC 8414 / OIDC
  discovery, RFC 7591 dynamic registration or a given client id, PKCE S256, RFC 8707 resource indicator, RFC 9207
  issuer check, refresh tokens). Sign-in opens a popup that returns to LUCID (needs LUCID over http/https).
* Tools appear to the model as `mcp__<server>__<tool>`; they need approval unless the server is marked trusted; in
  Ask mode only tools marked `readOnlyHint` are offered; results are wrapped as `untrusted_third_party_content`.
* The browser needs the server to allow CORS. For stdio servers and servers without CORS, put them in
  `~/.lucid-mcp/servers.json` — the bridge launches/proxies them at `/servers/<name>/mcp`:
```json
{ "mcpServers": {
    "files": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/cases"] },
    "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } } } }
```
